## 6. Про корпус: `reference_docs` — это не новый вариант, это то же самое

**Главный результат этой проверки.** `joined_reference` — ровно склейка
`reference_docs` через двойной перевод строки, побайтово:

| проверка | значение |
|---|---|
| `joined_reference` == склейка `reference_docs` | **1000 из 1000** |
| достижимость на `joined_reference` | 0,5235860126730815 |
| достижимость на `reference_docs` | **0,5235860126730815** |
| пересечение doc_id с test | 0 `reference_docs`, 0 `joined_reference`, 224 `docs` |
| все doc_id | 2174 `reference_docs` = 2174 `joined_reference`, 4282 `docs` |

Отсюда три следствия, которые исправляют пункт 6 разбора:

1. «Пересобрать на `reference_docs`» **нечего** — сборка уже на них. Это не изменение,
   а название того, что есть.
2. Достижимость на `reference_docs` **измерена** и равна нынешней: 0,5235860126730815.
   Строка «не измерено» заполняется этим числом, а не новым.
3. Разбиение на `reference_docs` **не ломается**: пересечение 0, как и сейчас.
   Ломается только вариант `docs` (224 doc_id = 0,052312003736571695).

**Значит выбор «`docs` или `reference_docs`» — это выбор между двумя разными вещами,
а не между «правильным» и «неправильным именем»:**

| | `reference_docs` (= сейчас) | `docs` |
|---|---|---|
| достижимость золотых токенов | 0,5235860126730815 | 0,7423140107955879 |
| медиана длины входа | 838 | 3919 |
| сумма знаков на 699 пар | 1544272 | 3021570 |
| медиана числа документов | 1 | 5 |
| пересечение doc_id с test | 0 | 224 (0,052312003736571695) |
| что это по смыслу | документ, на который сослался разметчик | документы, выданные поиском |

Ваш аргумент «в эксплуатации модуль получает найденные документы» **верен**, и он
означает, что честный вход — `docs`, а не `reference_docs`. Но тогда придётся принять
224 общих doc_id и пересобрать разбиение, иначе train делит документы с test.

## 7. Новая находка: что модель видела при генерации

В `Dataset/2_rushallu_rag_pairs/sberquad-train-rag.parquet` есть поле `prompt`
с фактическим входом генератора. Сверка на всех 1626 строках:

| проверка | значение |
|---|---|
| id в `prompt` == id в `docs` | 1619 из 1626 = 0,9956951931734317 |
| `reference_docs` ⊆ id в `prompt` | 1355 из 1626 = 0,8333333333333334 |
| `reference_docs` не пересекается с `prompt` вообще | 271 из 1626 |

**Оговорка, без которой это нельзя использовать:** это другой срез данных,
`query_id` с нашим gold не пересекается (655 против 1626, пересечение 0),
`model_output` не совпадает. Поэтому числа относятся к устройству поля `prompt`,
а не к нашим 699 парам, и переносить их на train/val я не вправе.

Что из этого следует по существу: в этом срезе модель-генератор получала **`docs`**
(пять найденных документов), а `reference_docs` — отдельное поле, иногда не
пересекающееся с показанным контекстом. Если то же верно для наших пар, то разметка
сделана относительно ответа, который строился на `docs`, а обучаем мы на
`reference_docs`. Это ровно тот дефект, который 55 нашла для `joined_reference`,
только теперь с другой стороны: не «модуль не видит половину контекста», а
«разметчик судил по другому контексту, чем тот, что попал в обучение».

Проверить это на наших 699 парах нельзя: в `1_rushallu_rag_gold/*.csv` поля `prompt`
нет. Это отдельная задача — сопоставить наши пары с parquet по `query_text`
(не по `query_id` и не по `model_output`).

скорость за норму 0,03 с. Это неверно: `speed52.py` считает
`ms_per_1000_doc = всё время / (сумма знаков документа / 1000)`, то есть **нормированную
величину**. Рост документа сам по себе норму не нарушает; на неё влияет только
квадратичный рост внимания. Мой вывод «скорость выходит за норму» снимаю.

генератор в наших парах. Пока это не сделано, любой выбор корпуса — догадка.
Локально, без обучения.

**Стадия B. Решение по корпусу — по результату A.** Если генератор видел `docs`,
честный вход — `docs`, и тогда обязательна пересборка разбиения на 224 doc_id.
Если `reference_docs` — оставить как есть, но записать в отчёт, что достижимость

**Стадия C. Пересборка + few-shot на выбранном корпусе.** Одной сборкой.

**Стадия D. Actions: перепрогон схемы 52, перезамер потолка 0,4791 и скорости.**

Мой ответ на ваш вопрос «на каком корпусе»: **`docs`**, но не как «более честный
