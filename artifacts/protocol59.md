## Что проверяется

Контракт модуля — `verify(answer, document, ...)`: **вопроса нет**. Метка же
устроена так, что большая часть её токенов определяема только относительно
вопроса. Проверяется единственная до сих пор не тронутая причина: если подать
вопрос на вход энкодера, станет ли метка достижимее.

## 0.1 Основная метрика

**token F1 на полной метке (все шесть типов)**, усреднение по парам через
объединённые счётчики (pooled), декодер поставки. Это то, что записано в
договоре. В основной строке отчёта подмены на подмножества нет.

## 0.2 Дополнительная строка: «документные» типы

Считается **всегда**, приводится рядом с основной, никогда вместо неё.

Подмножество: **Contradiction + Unconfirmed + Excess**. Основание — это
единственное подмножество, на котором наши цифры сопоставимы с RAGTruth и
LettuceDetect: там ложность определяется относительно документа, а не вопроса.
Подмножество зафиксировано здесь заранее, чтобы не выглядеть подгонкой.

Проверено по нашим 699 парам (`tools/preflight_13.our_rows`, 300 спанов):

| тип (`type_src`) | спанов | токенов | доля токенов |
|---|---|---|---|
| Partial | 91 | 4402 | 0,479 |
| Missing | 42 | 1736 | 0,189 |
| Unconfirmed | 79 | 1095 | 0,119 |
| Excess | 18 | 945 | 0,103 |
| Contradiction | 49 | 604 | 0,066 |
| Oversight | 21 | 409 | 0,045 |
| **всего** | **300** | **9191** | **1,000** |

- «относительно вопроса» (Partial + Missing + Oversight): **6547 токенов, 0,7123**
- «документные» (Contradiction + Unconfirmed + Excess): **2644 токена, 0,2877**

Числа промпта (0,478 / 0,189 / 0,045 → 0,712) воспроизводятся. Расхождение
с промптом в третьем знаке (2644 против 2660) — из-за подсчёта по
`covered_tokens`; для решения это несущественно.

## 0.3 Порог приёмки (не меняется)

token F1 ≥ 0,50 при FPR ≤ 0,40 на отложенной по документам части,
precision ≥ 0,45.

## 0.4 Базовые линии

К каждой цифре приводятся **обе** базовые линии, посчитанные тем же путём
метрик (`covered_tokens` + `token_positions`, метки из CSV):

1. **«пометить всё»** — предсказание покрывает все токены ответа;
2. **«all-positive»** — все пары помечены как содержащие ошибку.

Цифра без базовой линии в отчёт не идёт. Значения базлайнов уже посчитаны в
`artifacts/baselines58.json` и в протоколе не пересчитываются; для набора
699 пар all-positive token F1 = **0,5001320461281141**.

## 1.1 Архитектура (единственное изменение — вопрос)

Вход: `[CLS] question [SEP] document [SEP] answer`. Вопрос — часть первого
сегмента пары `(segment, answer)`; признаки `doc_overlap` считаются по
`(question + document)`. Модель, схема 52, гиперпараметры, число эпох,
декодер — без изменений.

## 1.2 Наличие вопроса в парах — проверено, найдено расхождение с промптом

В CSV (`Dataset/1_rushallu_rag_gold/sberquad-rag.csv`, `ruscibench-rag.csv`)
колонка `query_text` заполнена в **1000 из 1000** строк, средняя длина 64,7 и
74,1 знака.

**Но в парах её не было.** `tools/preflight_13.our_rows()` поля `query_text`
не переносил: из 699 собранных пар непустой вопрос имели **0**. То есть
«переносится без потерь» верно для CSV и неверно для кода. Поле добавляется в
`our_rows()` — это часть работы стадии 1, а не предположение.

## 1.3 Флаг

Существующий код параметризуется флагом `--with-question`
(`QUESTION_INPUT` в `spanver/lexfeat.py`), значение по умолчанию — `false`:
поведение без флага побитово совпадает с текущим. Контрольный прогон A идёт
тем же кодом с `--with-question=false`.

## 1.4 Два прогона, одинаковый протокол

10 фолдов по `doc_ids`, 5 сидов (0–4), схема 52, порог выбирается по
внутреннему фолду с ограничением FPR ≤ 0,40, внешний фолд не смотрится до
конца. Различие только флаг:

- **A (контроль):** `--with-question=false`;
- **B (опыт):** `--with-question=true`.

## Критерии 1.5–1.11

| # | критерий | порог |
|---|---|---|
| 1.5 | контроль A воспроизводит прежние числа | token F1 0,5119 ± 0,002, FPR 0,3896 ± 0,002 |
| 1.6 | опыт B: token F1 pooled | ≥ 0,55 |
| 1.7 | опыт B: FPR pooled | ≤ 0,40 |
| 1.8 | опыт B: token precision | ≥ 0,45 |
| 1.9 | отрыв B от базлайна своего набора | ≥ 0,05, нижняя граница CI выше базлайна |
| 1.10 | подмножество «документных» типов | обе цифры, A и B |
| 1.11 | CI 95 % bootstrap | для B |

## 1.12 Решающее правило (зафиксировано заранее)

- B ≥ 0,55 при precision ≥ 0,45 и FPR ≤ 0,40 → **гипотеза подтверждена**,
  переход в стадию 2 (п. 2.2).
- B в 0,52–0,55 → **частично**: направление верно, сигнала не хватило;
  стадия 2 по п. 2.1 (признак «вопрос» в скоринге спанов).
- B ≤ 0,52 → **гипотеза опровергнута**: вопрос на входе не помогает, причина
  в другом.

Любой исход публикуется с числами. Провал — такой же результат, как успех.
