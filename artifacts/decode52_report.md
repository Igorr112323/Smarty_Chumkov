## Новое правило (применяется во всех дальнейших отчётах)

1. Порог `start`/`extend = start/2` выбирается **только по внутренним фолдам**:
   объединённые целочисленные счётчики четырёх внутренних фолдов, ограничения
   `fpr_token <= 0.40` и `fpr_pair <= 0.40` по объединению, критерий — максимум
   объединённого token F1, при равенстве меньший порог. Это заменяет
   `tools/collect_nested38.py:26` (`max` по каждому внутреннему фолду).
2. `gate` и нормировка шкалы скоров по фолду **не** применяются до стадии 3:
   их пересчёт требует внутренних вероятностей, которых нет в артефактах.
   Текущий отчёт использует `gate = 0.45` как в сохранённых `inner_grid`.
3. Каждая таблица обязана содержать три строки базовых линий:
   all-positive token F1 = **0.5001320461281141**, all-positive pair F1 =
   **0.5095951249422134**, whole-answer span (IoU >= 0.5) F1 = **0.30430405718521835**.
4. Все метрики — с 95 % интервалом по документам (бутстрэп по связным
   компонентам общих `doc_id`, 10 000 ресэмплов, seed 48).

## Почему меняем правило

Прежнее правило требовало `FPR <= 0.40` на **каждом** из четырёх внутренних
фолдов, то есть максимум из четырёх шумных оценок. Внутренний фолд на 10-фолдовой
схеме содержит 41-54 отрицательные пары, поэтому один ложный спан сдвигает FPR
на 0.02-0.09 и правило систематически завышает порог (0.52-0.56 вместо 0.47-0.49).

(0.3788 -> 0.5074) и убирает нулевой фолд (min 0.0000 -> 0.3283). Но:

  IoU F1 = **0.30430405718521835**, новое правило — **0.2851**. Разница
