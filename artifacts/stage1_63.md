## 1.1 Нарезка на кандидаты

Правило: предложение; если длиннее 200 знаков — по границам клауз (`,;:`); плюс **объединения до трёх соседних единиц**; плюс кандидат «весь ответ».

| величина | значение |
|---|---|
| всего кандидатов | **5973** |
| на пару: медиана / среднее | 3 / 8.5 |
| на пару: мин / макс | 1 / 76 |
| длина: медиана | **121** знаков (цель 80–160) |
| длина: p10 / p90 | 23 / 300 |
| длина: мин / макс | 2 / 1554 |
| доля в диапазоне 80–160 | 33.8% |

Медиана 121 знак попадает в цель 80–160. p10 = 23 — это короткие предложения, они нужны для Contradiction (медиана 85) и Unconfirmed (81).

### Почему понадобились объединения: это не украшение, а исправление дефекта

Первая версия нарезки (только одиночные предложения и клаузы) дала оракул 0,9708 — выше, но **172 пары с положительным кандидатом против 239 с золотом**. 67 пар теряли метку, и модель физически не могла их найти.

Причина: 99 из 300 спанов (33,0 %) не отдавали 50 % токенов ни одному кандидату, потому что **медиана длины потерянных — 531 знак** против 78 у кандидата. Правило 50 % при таком соотношении невыполнимо.

| нарезка | кандидатов | потеряно спанов | оракул token F1 | длина med |
|---|---|---|---|---|
| одиночные единицы | 2514 | 99 (33,0 %) | 0.9708 | 78 |
| + объединения до 2 | 4329 | 50 (16,7 %) | 0.9099 | 100 |
| + объединения до 3 | 5746 | 25 (8,3 %) | 0.8727 | 117 |
| + объединения до 3 + весь ответ | 5973 | 0 (0,0 %) | 0.8237 | 121 |

Оракул падает при расширении набора — это нормально и ожидаемо: больше кандидатов, больше ложных срабатываний при «отметить всё, что пересекает золото». **Правильный выбор — покрытие метки, а не максимум оракула:** непокрытый спан модель не найдёт никогда, а лишние кандидаты она может отвергнуть обучением.

Остаток 17 пар имел золото, равное всему ответу (медиана 835 из 835 знаков); кандидат «весь ответ» закрыл их полностью.
