# V13 — аудит GitHub-репозиториев по span-детекции и перенос «логики без весов»

## Итог одной строкой

Из трёх репозиториев **ничего не портируется в рантайм**: все модели — torch-энкодеры/генераторы
на 66–7600 MB и без русского; всё, что можно перенести в stdlib (склейка прогонов, union-merge
спанов, sentence-snap, char-overlap метрика, выбор порога по max F1), на нашем val даёт максимум
`+0.019` Span при падении mFAVA `0.6895 → 0.5634` — guard (`+0.03` Span, mFAVA ≥ 0.65) **не пройден**,
изменение отклонено. Попутно зафиксирована главная причина «загадки цифр»: их Span 0.5–0.64 меряется
**другой конвенцией** (перекрытие символов), и наши же предсказания по ней дают **0.6514**.

### Сколько это в наших единицах

Наши предсказания v11 на val, прогнанные через **их** конвенцию (перекрытие символов):
precision `0.5763`, recall `0.7491`, **F1 `0.6514`**. Наша конвенция (Span F1 при IoU ≥ 0.5 на пару):
**`0.3363`**. То есть «Span > 0.50 там» и «Span 0.3363 у нас» — это разные метрики и разные языки;
одна и та же модель по их метрике уже «проходит 0.50». Вывод аудита: **их цифры не переносимы ни как
цель, ни как ориентир** без пересчёта конвенции.

## 2. Что удалось перенести в stdlib (`tools/port_lettuce_logic_v13.py`)

Перенесено (переписано с нуля, без torch/sklearn/numpy, только `re` и stdlib):

| функция | откуда | что делает |
|---|---|---|
| `runs_to_spans` | LettuceDetect `_build_spans_from_tokens` | склейка подряд идущих «плохих» токенов в чар-спан, confidence = max, отсечка `min_confidence` |
| `chunk_max` | LettuceDetect `_predict_chunked` | агрегация вероятностей по evidence-чанкам через max |
| `char_overlap_f1` | LettuceDetect `evaluate_detector_char_level` | микро-P/R/F1 по перекрытию символов |
| `merge_overlapping_spans` | faithful_eval `merge_overlapping_spans` | union-merge перекрывающихся спанов (у них — нормализация gold) |
| `build_char_mask` | faithful_eval `build_char_mask` | verbatim-поиск спана по всем стартам |
| `split_sentences` | HALO `spans.split_sentences` | предложения с точными чар-оффсетами |
| `best_threshold` | HALO `metrics.best_threshold` | порог, максимизирующий F1 на калибровке |

Сравнение с нашей текущей логикой:

| элемент | у нас (v11) | у них | новое? |
|---|---|---|---|
| кандидаты | клаузы/слова/предложения ответа | токены энкодера с offset-mapping | неприменимо: у нас нет токен-флагов |
| отбор спанов | IoU-NMS 0.1 + risk ≥ 0.6 + max_spans | прогоны токенов + `min_confidence` | нет |
| несколько чанков | нет (один документ) | max по чанкам | неприменимо |
| пересечения предскаzaний | NMS **выбрасывает** второй спан | **union-merge** объединяет | **да** |
| расширение до предложения | нет | sentence-level детектор (halo) | **да** (как пост-правило) |
| метрика | Span/Token/Pair F1 при IoU ≥ 0.5 | char-overlap / sentence-level | другая конвенция, наш контракт не меняем |
| выбор порога | grid по val | `best_threshold(max F1)` | эквивалентно: на наших кандидатах даёт `0.5737` (F1 0.5067) против нашего `0.6` |

## 3. Ablation на val + mFAVA (веса не менялись, только декод)

| вариант | val span | val token | val pair | FPR | mFAVA span | guard |
|---|---|---|---|---|---|---|
| baseline v11 hybrid | 0.3363 | 0.6191 | 0.4872 | 0.125 | 0.6895 | — |
| merge0 (union перекрытий) | 0.3363 | 0.6191 | 0.4872 | 0.125 | 0.6852 | ✗ |
| merge2 (union, зазор ≤ 2 символа) | **0.3551** | 0.6191 | 0.4872 | 0.125 | **0.5634** | ✗ |
| merge2 внутри предложения | 0.3393 | 0.6191 | 0.4872 | 0.125 | 0.6913 | ✗ |
| merge с капом 120 / 200 / 300 символов | 0.3363 / 0.3393 / 0.3333 | 0.6191 | 0.4872 / 0.4872 / 0.4675 | 0.125 | 0.6895 / 0.6639 / 0.5951 | ✗ |
| sentence-snap 0.6 / 0.8 | 0.3393 / 0.3363 | 0.6202 / 0.6191 | 0.4872 | 0.125 | 0.6702 / 0.6825 | ✗ |
| merge2 + snap 0.6 / 0.8 | 0.3551 / 0.3551 | 0.6202 / 0.6191 | 0.4872 | 0.125 | 0.5575 / 0.5605 | ✗ |
| **guard** | ≥ 0.3663 | ≥ 0.50 | — | ≤ 0.40 | ≥ 0.65 | — |

Прошедших guard — **0**. Лучший val-прирост (`merge2`, +0.019) покупается падением mFAVA на
`−0.126`: на длинных ответах union-склейка соседних клауз превращает несколько коротких спанов в один
длинный и убивает recall (`0.6701 → 0.4885`). Ограничение «только внутри предложения» mFAVA сохраняет
(`0.6913`), но даёт всего `+0.003` на val. `sentence-snap` даёт `+0.003`, `merge0` — ровно ноль
(после NMS перекрытий уже нет). 3-fold OOF **не запускался**: по правилу цикла он нужен только если
val дал плюс, а guard не пройден.

## 5. Вывод

GitHub-обёртка без весов проблему стиля RusHallu **не решает**: переносимая часть — это склейка
токен-флагов (у нас нет токенов), union-merge (портирован, guard не прошёл) и метрика другой
конвенции (объясняет разрыв цифр, но не приближает нас к цели). Наш реальный разрыв — не декодер
спанов, а выбор границы whole/clause на русских ответах; закрывать его нужно своим span-циклом, а не
портированием чужой обвязки.
