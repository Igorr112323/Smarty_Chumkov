# V21 — подготовка GPU-обучения cross-encoder: цепочка собрана и измерена, обучение блокировано отсутствием GPU

## Итог одной строкой

Вся цепочка «данные → архитектура → обучение → ONNX int8 → CPU-скорость → проверка» **собрана,
прогнана и измерена**, но **обучить cross-encoder не на чем**: в песочнице нет GPU
(`nvidia-smi` отсутствует, `/dev/nvidia*` нет, `torch.cuda.is_available() = False`). Метрики
val/OOF для cross-encoder не выдумываются — их нет. Span остаётся незакрытым: последний честный
результат — **0.3670** (v20) против требуемых 0.50.

## ШАГ 2. Архитектура (`tools/ce_model_v21.py`)

`CrossEncoderSpan` = **rubert-tiny2 с реальными весами** + три головы:

* `start` / `end` — логиты по токенам кандидата (BCE/CE), метка — gold-span внутри кандидата;
* `risk` — логит по CLS «в кандидате есть неподтверждённый фрагмент».

Веса энкодера взяты из локальных чанков §4.2: `weights/rubert-tiny2/part-000.bin + part-001.bin` →
`models/rubert-tiny2/pytorch_model.bin`, размер 117 546 024 B, SHA-256
`137fa2b1d944dae19c74456dfe8fac2f780d9acf34e037f5d1e37acba1157768` — **совпал с манифестом**.
Параметров 29 194 707 (fp32 111.37 МБ, int8 27.84 МБ). Вход:
`[CLS] document_prefix(200) [SEP] candidate [SEP]`, `token_type_ids` разделяет документ и кандидата.

## ШАГ 3. Обучение: пайплайн проверен, GPU-прогон не выполнен (`artifacts/ce_train_v21.json`)

Скрипт `tools/ce_train_v21.py` GPU-готов: автоопределение устройства, AMP (bf16/fp16),
grad accumulation, AdamW, батчи с балансом 50 % позитивов (иначе span-loss вырождается в 0),
обрезка градиента, чекпойнт, история по эпохам. На CPU выполнен smoke-прогон **без подмены
результата**:

| показатель | значение (CPU, 2 ядра) |
|---|---|
| шагов в smoke | 8 (batch 8, max_len 256) |
| медиана времени шага | **1.09 с** |
| шагов на эпоху (94 267 кандидатов, batch 8) | 11 784 |
| оценка эпохи на CPU | **214 мин** |
| оценка 3 эпох на CPU | **642 мин (10.7 ч)** |
| loss после 8 шагов | start 2.55 / end 2.78 / risk 0.66 — все три головы учатся |

То есть на CPU обучение нереально (совпадает с расчётом v17 «~50 мин/эпоху при меньшем батче»),
а на GPU-машине при типичном ускорении 20–40× это **5–15 минут на эпоху** (оценка, не замер —
GPU нет). Ablation `CE + real` / `CE + v19` / `CE + все данные` реализован флагом
`--limit` + выбором набора в данных: три прогона по 3 эпохи ≈ 45 минут на GPU.

**Control:** baseline v11 воспроизводится в харнессе точно — Span 0.3621 / Token 0.6247 /
Pair 0.5122 / FPR 0.1442 (v20 `blend_v20.json`, `reference_v11_reproduced`).

## ШАГ 4. Экспорт ONNX + int8 (`artifacts/ce_export_v21.json`, `artifacts/speed_v21.json`)

| шаг | результат |
|---|---|
| ONNX, opset | **17** (≥ 14 ✅), динамические оси batch/sequence |
| размер fp32 | 116 483 760 B (111.09 МБ) |
| int8 dynamic (QInt8) | **29 285 804 B (27.93 МБ)**, сжатие **3.98×** |
| паритет fp32 vs int8 | start/end: corr 1.0, max |Δ| 0.086 / 0.184; risk: |Δ| 0.055 |
| совместимость | `onnxruntime` 1.32.0, CPUExecutionProvider, 2 потока |

Замечание: экспорт не бит-детерминирован (два прогона дают разные SHA при одинаковых размерах) —
для продукта SHA фиксируется на финальном чекпойнте.

### CPU-скорость (int8, 2 потока, batch 1)

| окно | 128 | 192 | 256 | 384 |
|---|---|---|---|---|
| латентность форварда | **4.6 мс** | 8.2 мс | 12.1 мс | 23.3 мс |

| точка договора | штатный рантайм | кандидатов | int8 CE | итого | лимит | вердикт |
|---|---|---|---|---|---|---|
| 1k знаков | 0.0092 с | 8 | 0.032 с | **0.046 с** | 0.03 с | ❌ (полный перебор кандидатов) |
| 50k знаков | 0.2398 с | 12 | 0.048 с | **0.287 с** | 1 с | ✅ (3.5× запас) |
| 2M знаков | 11.07 с | 19 | 0.129 с | **11.89 с** | 60 с | ✅ (5× запас) |
| стресс: ответ 50k знаков | — | 1 240 | 15.0 с | — | 1 с | ❌ |

**Решение для 1k найдено и измерено: каскад top-k** (v11-риск уже ранжирует кандидатов, CE
переранжирует только верхушку):

| каскад | 1k | 50k | 2M |
|---|---|---|---|
| top-1 | 0.0138 с ✅ | 0.236 с ✅ | 11.74 с ✅ |
| **top-3** | **0.0230 с ✅** | 0.245 с ✅ | 11.75 с ✅ |
| top-5 | 0.0322 с ❌ | 0.2545 с ✅ | 11.76 с ✅ |

Вывод по инженерии: cross-encoder int8 **вписывается в §4.1 только как каскад** (top-3 на 1k,
top-5 на 50k/2M) и **только для коротких ответов**; при ответе на десятки тысяч знаков число
кандидатов растёт до сотен и лимит недостижим. Документ подаётся префиксом 200 токенов —
это осознанный компромисс по качеству (полный документ в cross-encoder стоил бы десятки секунд).

## ШАГ 5. Guard — метрик нет, потому что нет обученной модели (`artifacts/span_oof_v21.json`)

| критерий | требование | факт | статус |
|---|---|---|---|
| val Span | ≥ 0.50 | **нет чекпойнта** (последнее честное: 0.3670, v20) | ❌ |
| val Token / Pair / FPR | ≥ 0.50 / ≥ 0.50 / ≤ 0.40 | нет чекпойнта (v20: 0.6453 / 0.5195 / 0.1058) | — |
| OOF Span | ≥ 0.2637 | нет чекпойнта (v20: 0.2295) | ❌ |
| скорость | 0.03 / 1 / 60 с | каскад top-3: 0.023 / 0.245 / 11.75 с ✅ | ✅ |
| пакет | ≤ 0.6 МБ | 523 986 B, SHA `6bbc5044…d73a` — не изменился | ✅ |
| тесты / CLI / HTTP / web | ≥ 142 | **147 passed** | ✅ |

Пайплайн оценки проверен на необученном чекпойнте (`span_oof_v21_smoke.json`): `ce_eval_v21.py`
считает val AUC, подставляет скоры в декадер v11, калибрует пороги и выдаёт Span/Token/Pair/FPR —
на случайных головах ожидаемо AUC 0.452 и Span 0.2393. Это проверка работоспособности цепочки,
**в guard такие числа не идут**.

**Вердикт: `reject_by_blocker_no_gpu`.** Натяжек нет: метрики cross-encoder не получены, потому что
модель не обучена.

## ШАГ 6. Инженерия — не сломана

* рантайм `spanver/` не тронут: torch/onnx в нём нет, продукт работает как раньше (чистый Python);
* пакет 523 986 B (511.7 KB) ≤ 0.6 МБ, SHA `6bbc50448aeb9deadfb44df35e98023fc0132ac3e59e18c590ace9698ff7d73a` — **не изменился**;
* тесты: **147 passed** (142 договорных + 5 v19), CLI/HTTP/web не менялись;
* веса cross-encoder лежат отдельно (§4.2): ONNX int8 27.93 МБ в `artifacts/` (не в пакете).

## Что осталось сделать на GPU-машине (4 команды)

```bash
python tools/ce_train_v21.py --device cuda --epochs 3 --batch 32 --amp      # 5–15 мин/эпоху
python tools/ce_eval_v21.py  --device cuda --oof 3 --epochs 1               # val Span/Token/Pair/FPR + OOF
python tools/ce_export_v21.py --checkpoint artifacts/ce_model_v21.pt        # ONNX + int8
python tools/ce_speed_v21.py                                                # 1k/50k/2M (каскад top-k)
```

Ожидание (не факт): v19 даёт втрое больше span-супервизии, чем реальные 549 пар, и in-domain AUC
0.984 (v20) — cross-encoder должен поднять кросс-доменный AUC с 0.74 до ≳ 0.88, что и даёт Span ≥ 0.50.
Если после GPU-прогона Span останется ниже 0.50 — вариантов два: (а) больше реальных
клаузовых аннотаций (в v18 найдено, что открытых нет), (б) продуктовое смягчение порога
(текущий рантайм: Span 0.367 при Pair 0.52 и FPR 0.11).
