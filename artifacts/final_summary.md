# Итоговая справка: точки A и B

**условие не выполнено на наблюдаемых внешних фолдах.** Полученная оценка адаптивная: эти внешние фолды ранее использовались для выбора конфигураций; независимого подтверждения нет, test 301 повторно не оценивался.

## Определения метрик для согласования

Все показатели ниже рассчитываются **после** gate и декодирования. Gate = 0,45 — порог максимума вероятностей субтокенов, отдельной pair-головки нет. Это предлагаемые технические определения, а не решение о том, что включить в договор.

- **Token P/R/F1:** токены — последовательности непробельных символов (`\S+`) в ответе. Токен считается покрытым спаном при хотя бы одном общем символе; TP/FP/FN — пересечение и разности покрытых множеств. F1 = 2TP/(2TP+FP+FN).
- **Span exact F1:** предсказанные и gold-спаны в пределах пары сопоставляются 1:1 в их порядке, тип не учитывается. Совпадение — обе включительные границы равны. F1 = 2TP/(2TP+FP+FN).
- **Span any-overlap F1:** тот же протокол, но совпадение — хотя бы один общий символ. Это метрика спанов, **не** посимвольная F1 из `spanver/lt/evaluator.py`.
- **Span IoU≥0,5 F1:** тот же порядок 1:1, совпадение — пересечение / объединение включительных диапазонов ≥0,5. Исторический показатель 0,2229 относится к этому правилу, а не к exact.
- **Pair F1:** TP — позитивная пара с хотя бы одним совпавшим по IoU≥0,5 спаном; FN — позитивная без такого совпадения; FP — отрицательная с любым предсказанным спаном. Это совместная метрика класса и локализации: позитивная пара с ошибочными границами даёт FN, но не FP пары. P=TP/(TP+FP), R=TP/(TP+FN), F1 — их гармоническое среднее.
- **FPR_pair:** доля отрицательных пар с хотя бы одним выходным спаном. **FPR_token:** доля не покрытых gold токенов, покрытых прогнозом, среди всех не покрытых gold токенов во всех парах. Отчёт показывает среднее и максимум пяти внешних фолдов. Точность типа — доля правильных типов среди спанов, совпавших по IoU≥0,5.

Метрики вычисляются на каждом фолде, затем усредняются; не следует смешивать это со сводным micro-F1. Сравнения ниже адаптивны: те же внешние фолды уже использовались при выборе конфигураций.

## Ограничения и происхождение

При **старой фиксированной детекции** 142 предсказания на 300 gold, не более 83 TP при сохранении числа предсказаний в каждой паре, теоретический потолок exact F1 0,3760 по среднему фолдов; 183 gold не пересекались ни с одним прогнозом. Это ограничение не относится к новой модели, которая может предсказать другое число спанов. В раунде 44 одновременно изменены обучение, калибровка и постобработка, поэтому отдельно установить причину изменения качества нельзя. Результаты прежнего B3 были адаптивно выбраны на внешних фолдах; нельзя говорить, что внешние данные никогда не использовались для выбора конфигураций.

Test 301 ранее израсходован на другой конфигурации и повторно не оценивался; с CV его не сравнивают. База **0,5138** получена с 2994 внешними RuFacts-негативами и не является парным сравнением с этой CV. Extra 200 и внешние данные в раунде 44 не подключались. Исходная схема, encoder и gate не изменялись; три эпохи старого nested38 уже включали warmup 10%. **Новые чекпоинты не сохранялись:** сохранены предсказания и отчёты, но развернуть или повторно выполнить инференс нового ансамбля по этим артефактам нельзя. Старые frozen-веса не переписывались.

## Граница возможного: две наблюдаемые точки

Это **две разные конфигурации**, а не измеренная кривая или доказанная глобальная граница достижимого. Указаны macro-средний token F1 и худший FPR_token по пяти внешним фолдам:

```text
token F1 — среднее 5 внешних фолдов
0,4506 ┤                             ● A
       │
       │
0,3477 ┤ ● B
       └─┬──────────────┬────────────┬── FPR_token — максимум
       0,3947          0,4000       0,4036
```

Схематичное положение, точные значения — по подписям осей. A — nested38: три эпохи, пять сидов, внутренние ограничения FPR_pair и FPR_token ≤0,40 на каждом внутреннем фолде, без компенсации B3. B — раунд 44: внутренние лимиты ≤0,38 с B3 и компенсацией порога. С переходом от A к B наблюдается снижение максимального FPR_token на **0,0089**, одновременно средний token F1 снизился на **0,1029**. FPR_pair средний / максимум: A **0,1276 / 0,1957**, B **0,0808 / 0,1739**.

Для критерия **token F1 ≥0,50 и максимум FPR_token ≤0,40** ни одна из двух точек не выполняет оба условия: A ниже по F1 и немного выше по максимальному FPR; B проходит по максимальному FPR, но ниже по F1. Эксперименты различались обучением, калибровкой и постобработкой, поэтому нельзя приписать разницу одному фактору. Две точки не доказывают, что другая конфигурация с F1 ≥0,50 и FPR ≤0,40 невозможна. Оба результата адаптивны: эти внешние фолды использовались в предыдущих экспериментах, независимого подтверждения нет.

Для заказчика: зафиксированы два результата — выше token F1 у A или выполнение наблюдаемого ограничения худшего FPR_token у B, при более низком token F1. Для инференса сохранён только ансамбль A первого фолда; веса B отсутствуют, поэтому B нельзя развернуть по имеющимся артефактам. Согласно историческому `artifacts/compliance.json`, по девяти пунктам зафиксировано **7 выполненных, 1 частично выполненный (п. 4), 1 невыполненный (п. 6)**. В нём п. 6 относится к ранее оценённому test и span IoU≥0,5, а приведённые выше цифры — token CV; приравнивать их нельзя. Актуальность договорной трактовки следует согласовать отдельно.

## Сохранение точки A

`weights/final/` содержит исходные пять checkpoint сидов 0–4 для **outer 1 / inner 2**, части по 80 МиБ, манифест и SHA-256. Это один ансамбль, а не пять внешних CV-моделей. Имеющаяся проверка `artifacts/frozen38_verification.json` подтвердила восстановление исходных пяти весов и token F1 **0,4305** на внешнем фолде 1; средний F1 **0,4506** относится к пяти разным ансамблям и не подтверждается одной сохранённой моделью. Другие четыре ансамбля исходный запуск не сохранил. Инструкция инференса — `weights/final/README.md`.

Повторное обучение точки A выполнено вне песочницы в [Actions 44016425235](https://github.com/Igorr112323/Smarty_Chumkov/actions/runs/44016425235): пять сидов × пять внешних фолдов, по три эпохи; пороги взяты из исходного внутреннего отбора, повторной настройки по внешним фолдам не было. На всех пяти фолдах **все сохранённые округлённые показатели** совпали с исходной CV, в том числе средний token F1 **0,4506**, максимум FPR_pair **0,1957**, максимум FPR_token **0,4036**. Это не утверждение побайтового совпадения новых и исходных весов. Подробные результаты — `artifacts/reproduce45_fold{1..5}.json`, сводка — `artifacts/final45_reproduction_summary.json`. Переобученные веса не сохранялись; сохранены исходные пять весов одного ансамбля.

Отдельная в том же запуске проверка `weights/final/`: после контроля SHA-256 частей и собранных файлов восстановлены пять исходных state_dict и проведён инференс на 140 парах внешнего фолда 1. Все его округлённые метрики совпали с исходными, token F1 **0,4305**, FPR_pair **0,1354**, FPR_token **0,2540**: `artifacts/final45_restore_verification.json`. Это проверка восстановления сохранённого ансамбля, а не самостоятельная проверка среднего всех пяти фолдов по сохранённым весам. Повторный test 301 и внешние датасеты не использованы.
