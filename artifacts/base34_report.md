# Дефекты прогона rubert-base

Исходный прогон: два фолда; по условию куратора результат не засчитывается как валидный результат схемы 4. Диагностика не обучала модель и не использовала test 301. Исходный артефакт с checkpoint использовался только для чтения в Actions; новый артефакт содержит только JSON.

## 1. Нулевой первый фолд

Checkpoint fold 1 загружен строго: True; SHA-256 `eb7a930ff4a4aaca431fa79a2eef5ff517c843497d3b450e3d462fb5ba68a5d6`. На отложенном фолде получены вероятности для 349 из 349 пар. Через gate 0,45 проходят 124 пар, но ни в одной нет субтокена с вероятностью ≥ 0.55; при start 0.55 и extend 0.10 выдано 0 спанов в 0 парах. Исходные метрики воспроизведены.

В исходной сетке 171 сочетаний, из них 126 удовлетворяют обоим FPR ≤ 0,40; среди них нет ни одного с ненулевым token F1. Поэтому выбор пустого предсказания — следствие ограничений и правила выбора, а не ошибка загрузки. Без ограничений лучшая по token F1 диагностическая точка 0.40/0.40: token F1 0.5374, span F1 0.2857, FPR_pair 0.2324, FPR_token 0.5398. Она нарушает лимит FPR_token и не считается исправленным результатом.

В тренере добавлен подсчёт предсказанных пар и спанов; при нуле спанов фолд теперь помечается STOP и общая CV-сводка не выдаётся как успешная. Причину невозможности получить ненулевую допустимую точку это не устраняет; выдавать пригодную оценку без изменения ограничений нельзя.

## 2. Проверка mean ± std

В исходном JSON 0,3137 — средняя token precision, а не token F1. Обе сводки вычислялись по двум фолдам со стандартным отклонением генеральной совокупности (ddof=0). При значениях 0 и x среднее равно x/2, и такое std тоже равно x/2; это не признак выборки из одного фолда. Независимый пересчёт совпал с исходным JSON после округления для всех метрик.

Эти цифры являются проверкой арифметики исходного невалидного прогона, а не новой оценкой схемы 4. Для наглядности подсчёт сводки вынесен в отдельную функцию и покрыт тестом.

## 3. Энкодер и learning rate

Оба checkpoint загружены строго и сравнены с теми же исходными весами, подтверждёнными SHA-256. Группы optimizer восстановлены из исходного кода; runtime-снимок optimizer не сохранялся.

| фолд | всего параметров в группах | энкодер и embeddings | голова | изменённых элементов в 12 слоях относительно старта | изменённых тензоров слоёв |
|---:|---:|---:|---:|---:|---:|
| 1 | 177858818 | 177262848 | 595970 | 85053524 / 85054464 | 192 / 192 |
| 2 | 177858818 | 177262848 | 595970 | 85053342 / 85054464 | 192 / 192 |

В коде все параметры этих групп имеют requires_grad и передаются AdamW; веса 12 слоёв изменились относительно исходного checkpoint. Версия о замороженном энкодере данными не подтверждается; повторное обучение фолда 2 не запускалось. Состояние конца первой эпохи не сохранялось, поэтому сравнение именно эпохи 1 с эпохой 3 не проверено. Изменение весов показывает обновление относительно старта, но не заменяет отсутствующий промежуточный снимок.

Фактические LR в лог не записывались. По коду планировщика восстановлены LR, применявшиеся на шагах обоих фолдов (22 шага на эпоху, всего 66, warmup 6):

| эпоха | encoder первый → последний | head первый → последний |
|---:|---:|---:|
| 1 | 0.0000033333 → 0.0000150000 | 0.0000833333 → 0.0003750000 |
| 2 | 0.0000146667 → 0.0000076667 | 0.0003666667 → 0.0001916667 |
| 3 | 0.0000073333 → 0.0000003333 | 0.0001833333 → 0.0000083333 |

У второго фолда исходный span F1 0,1087 при FPR_pair 0,0091 и FPR_token 0,0539. Он ниже прежней базы 0,2982, но это один фолд, с другим составом обучения и подбором на том же отложенном фолде. Это не доказывает, что размер модели не влияет на качество.
