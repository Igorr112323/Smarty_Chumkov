# Инцидент: непреднамеренный запуск старого cli52 по push

Push коммита `9dbbefe8be9f7693e926eede6eda23be0ced70fb` с исправлением `spanver/tiny_backend.py` совпал с path-фильтром старого `.github/workflows/cli52.yml` и запустил [Actions 45151353019](https://github.com/Igorr112323/Smarty_Chumkov/actions/runs/45151353019). Это нарушение изоляционного плана и ошибка проверки триггеров перед push.

По API GitHub: job `acceptance` сделал **полный checkout**, установка завершилась успешно, шаг `data` завершился ошибкой. Шаги `weights`, `acceptance`, `contract`, `pytest` пропущены. Шаг `data` по workflow сначала запускает `tools/read_parquet.py`, а затем `spanver build --dataset Dataset`, который читает общий gold, включая test 301. Логи шага из этой песочницы недоступны (EOF от results receiver), поэтому **неизвестно, на какой команде произошла ошибка и успел ли процесс прочитать test 301**. Полный checkout предоставил Dataset раннеру; это нельзя называть безусловной изоляцией test. Никакие выходные данные и метрики случайного запуска не использовались; подбора по test и обучения в нём не было.

Независимые запланированные задания 45151350705 и 45152394711 использовали sparse checkout без Dataset и только проверенный файл 699 train/val. После обнаружения инцидента push-триггер в `cli52.yml` удалён, а сам job для активной ветки отключён даже при ручном dispatch. `ci.yml` и `evaluate.yml` также не имеют push-триггеров. Перед будущими push нужно проверять все workflows с path-фильтрами, а не только ci/evaluate.
