# Tiny V5 seed 0: поставка и проверка загрузки

Модуль `TinyBundle` теперь загружает проверенный checkpoint после создания базовой модели. Перед инференсом он проверяет manifest V5, seed 0, размеры частей и SHA-256 частей и полного checkpoint (`04eb7932a33a7ed1a2f4e166f536b002ba3ad4a16e2a410a21e292e1558d747a`), затем выполняет `load_state_dict(..., strict=True)`. При отсутствующих или повреждённых весах он сообщает `TinyUnavailable` и **не** выдаёт результат случайной головки. Нужны Python, torch, transformers, локальный `models/rubert-tiny2`, `artifacts/tiny_head.json`, `weights/final/manifest.json` и все части из `weights/final/seed_0/`. Файл кода пакета и веса поставляются отдельно.

Исторические веса доступны как артефакт `weights47-v5-outer1` run `44056101776`. В Actions проверки используется манифест `weights/final/manifest.json` из `arena/5afadcb0-smarty-chumkov`, а из архива копируется только `seed_0` в `weights/final/`. Части также проверяются при каждом запуске, манифест один не является доказательством целостности. Базовые файлы модели собираются локально из `weights/rubert-tiny2/` через `tools/assemble_weights.py`; сетевые вызовы внутри самой модели не выполняются.

Параметр `--weights` CLI и первый аргумент `TinyBundle` по-прежнему обозначают каталог базовой модели; путь к checkpoint по умолчанию `weights/final`, при необходимости в явном JSON-профиле доступны `checkpoint_dir` и `checkpoint_sha256`. Указание нестандартного SHA означает использование другой явно выбранной модели, оно не подтверждает происхождение V5. Лексический режим без изменений. Пороги и декодирование V5 не менялись.

`test_split64.py` в изолированном pytest помечается `skip` сборщиком с причиной «требует данных test 301, не читаются по политике», исходный код тестов не изменяется. Тест наличия вопросов использует сохранённую train/val выборку и не проверяет импорт из исходного CSV.
